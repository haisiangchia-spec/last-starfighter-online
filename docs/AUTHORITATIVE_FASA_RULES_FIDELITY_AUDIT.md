# Authoritative Rules Fidelity Audit — The Last Starfighter (FASA, 1984)

**Source of truth:** *The Last Starfighter* (FASA Corporation, 1984), 24-page PDF supplied by the project owner on 2026-11-08, credited to Jordan Weisman (design), L. Ross Babcock III (development), and Wm. John Wheeler (writing/editing). The exact PDF has been saved in the owner's ChatGPT Library at `/Last Starfighter/Last Starfighter Rules (1984 FASA authoritative).pdf`. This repository report does not reproduce the copyrighted rules or diagrams.

**Scope:** Source inspection of `game.html` (local), `online-battle.js` (multiplayer 1v1 / 2v2 / Swarm), `online-battle.html`, `tests/combat.test.cjs`. This is a rules audit, *not* a validated full gameplay run. The original boardgame contains Duel and Ko-Dan Swarm; **2v2** is allowed by its multiplayer guidance, but our particular team UI is an adaptation.

## Status definitions

- **Implemented:** source supports the main described mechanic; not a claim of exhaustive correctness.
- **Partial:** related support exists, with specific observable gaps.
- **Missing:** rulebook mechanism absent from code or its player-facing selection interface.
- **Deviation:** implemented behavior differs from a clear printed rule.
- **Needs validation:** cannot establish full compliance from code inspection alone.

## Acceptance gates before “rulebook-faithful”

1. Fix deliberate **empty-asteroid-hex photon targeting** for local and online, with two-phase networked target declaration and collision-free removal.
2. Fix unconditional **three-turn parser** to respect forced-turn damage exceptions.
3. Fix **asteroid-on Swarm deployment**; introduce selectable/valid large clusters or clearly identify simplified random clusters as a house rule.
4. Add networked Swarm **Death Blossom**, including six directional shots and full-turn recovery.
5. Add emulator-backed 1v1/2v2/Swarm browser E2E tests exercising damaged movement, target declarations, asteroid clearing, ammo, power/recharge, victory/reconnection.
6. Reconcile all prior secondary-rule claims against this PDF; this upload takes precedence.

**Audit caveat:** Do not treat “84 combat tests passed” as 84 fully independent rules validations. Tests can reflect assumptions already encoded in the implementation and do not replace comparison against the primary PDF.

## Implementation update — 2026-11-08: asteroid clearing and damage-driven steering

The above table records the **baseline at audit time**. The following work was subsequently committed:

- `online-battle.js`: The vector parser accepts any 0–5 F/L/R sequence and leaves the three-turn ceiling to `predict()`, which understands steering-lock, stabilizer, and constant-speed exceptions. Undamaged ships still cannot plan four turns. **Implemented; source-level tested.**
- `online-battle.js`: Photon missile targeting now offers legal `asteroid:q,r` target IDs (no enemy required in that hex), includes the FASA p.19 +1 asteroid penalty, resolves missile shots against the selected hex in **1v1 and 2v2**, expends missiles on both hit and miss, and clears the targeted hex only on a hit. The pre-existing `missileBlast()` applies damage solely to occupants of the target hex. **Implemented; source-level tested.**
- `game.html`: Local target dropdowns also offer empty asteroid hexes for photon missiles; hit/clear uses the local missile dice, deferred duel damage and destruction sequencing. **Implemented; syntax checked, browser E2E not yet verified.**
- `tests/combat.test.cjs`: Added four tests for forced steering, asteroid target availability and hit number, 1v1/2v2 clearing, and blast confinement. **88/88 source-level checks passed** at commit `58c3cbc` (not a verified GitHub Actions result).

**Remaining:** Browser/emulator verification; rock-click target selection (dropdown is present); Swarm-mode explicit asteroid selection; simultaneous multiple missile effects in the same cluster; original seven-hex asteroid-counter geometry and asteroid-on Swarm setup; online Death Blossom. The above P0 rows should not be interpreted as fully closed for all modes.

## Implementation update — 2026-11-08: Ko-Dan Swarm fidelity pass

- **FASA p.21 Swarm deployment:** The online combat engine's `initialSwarm(false)` now starts the Gunstar at (5,6), facing east, with two outward-facing waves at x=10 and x=12. `initialSwarm(true)` starts the Gunstar on the west edge at (0,6), facing east, with two inward-facing waves at x=16 and x=18, facing west. Initial asteroid placement excludes all 15 starting ship hexes. Regression tests cover both variants across three seeds.
- **FASA p.19 Swarm asteroid clearing:** The Gunstar's photon missile may now select an empty `asteroid:q,r` target in the Swarm engine; a declared shot expends one missile, rolls against the asteroid-penalized target number, damages ships in the specified hex only, and clears that hex on a hit. A new source-level test verifies this.
- **Source-level status:** 91/91 tests passed in the isolated production-engine harness at commit `fd65e58`. This is not a claim of current green GitHub Actions.
- **Important scope restriction:** `index.html` and `firestore.rules` still prevent online Swarm matchmaking. The Swarm combat engine's coverage is preparatory, **not a playable online feature**. The local AI Swarm mode remains the supported Swarm route.
- **Outstanding for full fidelity:** Large seven-hex asteroid counters and configurable asteroid placement; online Swarm Death Blossom and enabling multiplayer Swarm (when tested); browser emulator verification of revised multiplayer target selection, plus all unresolved fidelity audit entries above.

## Locked house-rule exception — asteroid setup (2026-11-08)

The owner explicitly **removed manual asteroid placement** from the fidelity target. On **every asteroid-enabled map**, both the local game and online engines now automatically generate:
- **Exactly two large asteroid counters**, each consisting of a central hex and six surrounding hexes;
- **10 to 20 small single-hex asteroid counters (inclusive)**, with count and positions derived deterministically from the match seed.

The engine avoids overlapping asteroid hexes and provides at least one clear hex between every asteroid and all starting ships. The seeded layouts may differ between Duel, 2v2, and Swarm because ship starting coordinates differ; each scenario reproduces the same layout for the same seed. Small and large asteroid hexes continue to use the existing per-hex collision, line-of-sight, and photon-missile-clearing rules.

**This is intentional rather than a missing feature. Do not schedule player-chosen asteroid count, manual placement, or exact printed counter-placement procedure for future work unless the owner changes the house rule.**

Source-level regression verification: **94/94 tests passed** after the four-ship clearance correction. Browser CI has not yet been verified green for these commits.
